# 실험 A. 추론 경로 비교

**목적**: decode를 얼마나 줄일 수 있고, 줄이면 무엇을 잃는가.

**대상**: 스모크셋 30클립, 닫힌 집합 필드 전체 + 인과 귀속

## A.1 생성과 점수화 — 실행 차이

기준 사례: `id=42` 이륜차의 `turn_signal` 필드.

### 공통 입력

```
[이미지 토큰]  <영상: 11.2s~18.9s, 8프레임, 전방·전방우측 뷰>

[질문]
  주행 영상에 사건 메타데이터를 부여한다. 지정된 값 집합에서만 선택한다.
  [어휘 정의] turn_signal: on_left | on_right | hazard | none | not_visible
  [관측 객체] id=42  종류=motorcycle  위치=전방우측 9.8m, 횡오프셋 -2.6m, 속도 11.3m/s
  질의: id=42의 방향지시등 상태
```

### 생성 경로

프롬프트를 **질의까지** 보내고 값을 만들게 한다. 호출: `max_tokens=50`, `guided_json`.

```
prefill 17,660 토큰 → 마지막 위치 분포
decode 1..10 → {  "  turn  _signal  "  :  "  none  "  }
```

받는 것: `{"turn_signal": "none"}` — **값 하나.** `on_right`가 몇 점이었는지는 알 수 없다.

### 점수화 경로

프롬프트를 **값 자리까지** 쓰고 후보를 이어붙인 변형 N개를 만든다. 호출: `max_tokens=0`, `prompt_logprobs` 활성. **decode 0회.**

```
변형 1  ... 질의: id=42의 방향지시등 상태\n{"turn_signal": "on_left"
변형 2  ...                                {"turn_signal": "on_right"
변형 3  ...                                {"turn_signal": "hazard"
변형 4  ...                                {"turn_signal": "none"
변형 5  ...                                {"turn_signal": "not_visible"
```

변형들의 앞 17,660토큰이 동일하므로 캐시 히트, 실제 계산은 후보 토큰 2~4개씩.

| 후보 | 토큰별 확률 | 곱 | 길이 정규화 |
|---|---|---|---|
| none | 0.62 | 0.620 | 0.62 |
| on_left | 0.21 × 0.71 | 0.149 | 0.39 |
| on_right | 0.21 × 0.28 | 0.059 | 0.24 |
| not_visible | 0.09 × 0.95 | 0.086 | 0.29 |
| hazard | 0.02 | 0.020 | 0.02 |

후보 집합 내 재정규화 → 답 `none`, 확신도 0.66, 2위 `on_left` 0.16.

### 정리

| | 생성 | 점수화 |
|---|---|---|
| 프롬프트 끝 | 질의까지 | 값 자리까지 + 후보 이어붙임 |
| decode | 값 토큰 수만큼 | **0** |
| 요청 수 | 1 | 후보 수 (캐시 공유) |
| 받는 것 | 문자열 | 후보별 확률 전부 |
| 스키마 위반 | guided_json으로 억제 | 정의상 불가 |
| 자유 서술 | 가능 | **불가** |

**생성은 쓰게 하는 것, 점수화는 이미 쓴 것을 채점하는 것.** 같은 forward 연산, 방향만 반대.

## A.2 CoT를 붙이는 방법

점수화는 값 자리에서 프롬프트가 끊기므로 **`<think>`를 쓸 자리가 없다.** 붙이려면 2단계.

```
1단계 (decode)
  ... 질의: id=42의 방향지시등 상태
  <think>  → 모델이 추론 생성 → </think> 까지 decode

2단계 (점수화)
  ... 질의: ...
  <think>우측 인접 차로의 이륜차. 프레임 3부터 횡오프셋이 -2.6m에서
  -1.4m로 줄어들어 자차 경로로 접근 중. 후미 광원은 상시 점등이며
  점멸 주기 미관측. 좌측 지시등 위치는 시야 가림. 점등 근거 없음.</think>
  {"turn_signal": "on_left"        ← 후보 5개 변형
```

- 추론은 **에피소드당 1회**만 생성하고 전 필드가 공유
- 추론 구간도 캐시되므로 필드당 추가 계산 미미

## A.3 arm 구성 (확정)

| arm | 1단계 | 2단계 | CoT |
|---|---|---|---|
| **A1** | 없음 | 점수화 | **명시적 억제** |
| **A2** | `<think>` decode 1회 | 점수화 | **명시적 요청** |
| **A3** | 없음 | 생성 (`guided_json`) | 명시적 억제 |
| **A4** | `<think>` decode 1회 | 점수화 + 앞 필드 확정값을 문맥에 추가 | 명시적 요청 |

**인접 쌍이 정확히 한 변수만 다르다.**

| 비교 | 다른 변수 | 판정 |
|---|---|---|
| A1 ↔ A2 | CoT 유무 | **CoT의 값어치. 이 수치 없이 경로 전환 금지** |
| A1 ↔ A3 | 점수화 / 생성 | 경로 대체 가능성. **요청 수가 아니라 실측 wall-clock으로 판정** |
| A2 ↔ A4 | 조건화 강도 | 일관성 이득 vs 오류 전파 |

### 통제 요구

Cosmos-Reason 계열은 CoT를 내도록 후학습되어 **요청하지 않아도 추론 토큰을 생성하려는 경향**이 있다.

- A1·A3은 추론을 **명시적으로 억제** (프롬프트 지시 + 필요 시 `</think>` 강제 종료)
- A2·A4는 **명시적으로 요청**
- 억제·요청 프롬프트 문구를 기록하고 arm 간 동일하게 유지

통제하지 않으면 arm 차이가 무엇 때문인지 알 수 없다.

### 예상되는 결론 형태

인과 귀속처럼 난이도가 높은 필드에서 A1의 저하가 클 가능성이 있다. **필드별로 다른 경로를 배정하는 결론이 나올 수 있으며, 그것이 오히려 자연스러운 결과다.**

## A.4 옵션 — 재프리필 (arm 아님)

A3의 **후처리**다. 생성이 끝난 JSON을 다시 프리필하면 값이 모두 채워져 있으므로 **한 번의 프리필로 전 필드 값 자리의 분포**를 얻는다.

- **라벨은 바뀌지 않는다.** 얻는 것은 필드별 확신도·후보 분포·엔트로피
- 용도: 검수 대상 선별. A3을 채택할 경우 신뢰도 계층을 확보하는 방법
- 한계: 모델이 스스로 쓴 값에 조건화된 확신도이므로 "정답일 확률"인지 "자기 답에 대한 확신"인지는 gold 대비 calibration으로만 구분

arm 비교에 넣지 않는다.

## A.5 기준선 측정에 관하여

현행 방식(제약 디코딩 1회)의 수치가 보고에 필요하면 **별도로 1회 측정하고 문서에 남긴다. arm 비교에는 넣지 않는다.**

이유는 두 가지다.
- 현행 방식은 CoT 상태가 **미통제**다. 요청도 억제도 하지 않으므로 실행마다 추론 발생 정도가 다를 수 있고, 재현되지 않는 기준선은 기준선이 아니다
- 현행 방식과 A1을 비교하면 CoT 유무와 생성/점수화 두 변수가 동시에 달라져 해석이 불가능하다

**측정과 판정을 섞지 않는다.** 보고용 기준선은 측정이고, 설계 선택은 A1~A4 안에서 판정한다.

## A.6 측정 지표

| 지표 | 용도 |
|---|---|
| 필드별 gold 대비 정확도 | 품질. 전체 평균 단독 금지 — 필드별·조건별 분해 |
| 클립당 wall-clock | 처리량 |
| decode 토큰 수 | 비용 분해 |
| 스키마 위반율 | A1·A2·A4는 정의상 0 — A3 대비 이득 확인 |
| 후보 분포 엔트로피 | 모호 케이스 식별 신호의 유효성 |
| 필드 간 모순율 | A4 ↔ A2 |
| CoT-점수 불일치율 | 추론 결론과 채점 결과가 갈리는 비율. **불일치가 큰 필드가 CoT 의존 필드이며, 그 목록이 경로 배정표의 근거** |
| 확신도의 오답 선별력 | 확신도 하위 구간에 오답이 몰리는지 |

## A.7 구현 요구

### 필수 스위치 (설정 교체 가능, 하드코딩 금지)

| 스위치 | 값 |
|---|---|
| `inference_path` | `scored` / `generated` |
| `scoring_method` | `sequence` (기본) / `first_token` |
| `cot_mode` | `suppress` / `request` |
| `conditioning` | `weak` (기본) / `strong` |
| `reprefill_enabled` | on / off |

### 점수화 구현 주의

1. **후보는 프롬프트 말미에만** 배치. 캐시 블록 경계에 걸치면 해당 구간 확률이 재계산되지 않을 수 있다
2. **길이 정규화** 후 비교. 토큰 수가 다르면 로그확률 합이 짧은 후보에 유리. 정규화 방식을 고정하고 기록
3. **first-token은 기본값이 아니다.** 충돌 없음이 검증된 필드에만 허용 (실험 B 산출물)
4. **다중값 필드**는 조합 나열 금지 → 후보별 이진 채점, 순서는 계측 시각으로 결정
5. **자유 서술 필드는 점수화 불가** → 구조 필드 확정 후 decode 1회

### 재현성

동일 설정 2회 실행 출력 해시 일치. 배치 크기·프리픽스 캐시 히트에 따라 부동소수점 합산 순서가 달라질 수 있으므로 매니페스트에 서빙 설정 포함.

# 실험 B. first-token 충돌 실측

**목적**: 빠른 경로(first-token 점수화) 적용 가능 필드 확정

**방법**: 어휘의 닫힌 집합 전 필드 값을 실제 토크나이저에 통과시켜 첫 토큰 ID 표 생성 → 필드별 충돌 목록 산출

**현재 상태**: 선두 3자 프록시 기준 38개 값에서 충돌 확인(대부분 좌/우 쌍). 실제 토크나이저 검증 필요

**산출**: 필드별 `scoring_method` 배정표 (`first_token` 허용 / `sequence` 강제)

**소요**: 짧음. 서빙 없이 토크나이저만으로 가능 → **즉시 실행 가능**

# 실험 C. GT 주입 배치

**목적**: 필드별 GT 배치 정책(DV-8) 확정 및 VLM 불필요 필드 선별

**대상**: 스모크셋 30~50클립, 3 arm

| arm | 구성 |
|---|---|
| all-before | 전 GT를 영상 앞에 배치 |
| all-after | 전 GT를 영상 뒤에 배치 |
| policy | 확정된 3-way 정책 적용 (`gt_only` / `gt_before` / `gt_free`) |

**측정**

| 지표 | 판정 |
|---|---|
| 필드별 gold 대비 정확도 | 배치의 품질 효과 |
| GT-모순율 (모델이 GT와 다른 값을 낸 비율) | all-after에서만 0이 아니어야 정상 — 검증 기능 작동 확인 |
| 복사율 (출력이 GT와 완전 일치하는 비율) | 높은 필드는 `gt_only`로 강등 = VLM 불필요 판정 |
| 클립당 토큰 비용 | 처리량 |

**상충 판정 완료**: 지침서는 GT 주입을 **3-way로 확정**했고 영상 뒤 주입(`gt_after`)은 기본값에서 제외했다(모순 탐지는 독립 실행 후 사후 대조로 대체). 따라서 본 실험의 all-after arm은 **반증 arm** — 주입이 라벨 정확도를 실제로 높이는지 확인하는 용도이며, 이득이 확인되면 `gt_after` 재상정.

**부속 확인**: 3DOD·지도 정보의 전달 형식(텍스트 직렬화 / 이미지 오버레이 / 병행)도 이 실험에서 함께 본다. 외부 연구에서 주 이미지에 직접 오버레이한 구성이 프롬프트를 분리한 구성보다 낮은 성능을 보인 사례가 있고, 개방형 백본에서는 마크 기반 시각 프롬프트가 전이되지 않는다는 보고도 있으므로 **오버레이 사용은 검증 대상**이다. 비교군: 좌표 텍스트만 / 주 영상 오버레이 / **별도 채널 분리**.

# 실험 D. 모델 대조군

**목적**: 주행 도메인 후학습이 태깅 품질에 기여하는 정도 분리

| 조건 | 모델 |
|---|---|
| 실험군 | 현행 Cosmos-Reason 계열 서빙 버전 |
| 대조군 | 동일 아키텍처 계열 base 모델 최신 버전, 동일 파라미터 규모 |

**성립 조건**: 현행 모델이 해당 base 가중치에서 초기화되었다는 **체크포인트 계보 확인 선행**

**설계**
- 프롬프트·입력·평가셋 동일. 모델만 교체
- 필드군별 분해 보고 필수 — 전체 평균은 의미 없음. 주행 특화의 이득이 특정 필드군(거동·인과)에 몰릴 가능성
- 참고: 외부 연구에서 유사 비교가 base 모델과 큰 차이 없음을 보고한 사례가 있다. 태깅 태스크에서도 그런지는 열린 질문

**부수 효과**: 대조군 실험이 성립하려면 모델 교체가 인터페이스로 격리되어야 한다. 이 실험 자체가 격리 여부의 점검이 된다
